# Метрики

## 1. Призначення

Модуль метрик забезпечує збір і виведення показників швидкодії прошивки, періодичності задач, затримки реакції на кнопку, завантаження процесора, журналу подій та використання пам’яті. Для зовнішнього спостереження за тривалістю задач використовуються службові GPIO.

## 2. Час виконання задач

Для кожної задачі збираються кількість вимірювань, мінімальний, середній і максимальний час виконання.

| Назва задачі | Призначення | Налаштований період |
|---|---|---:|
| `uart_rx` | Приймання UART | Не заданий |
| `sensors` | Обробка сенсорів | 100 мс |
| `camera` | Робота з камерою | 50 мс |
| `flash_log` | Запис журналу у flash | 500 мс |
| `heartbeat` | Періодична службова задача | 500 мс |

Виводяться такі показники:

| Метрика | Поле | Опис |
|---|---|---|
| Кількість вимірювань | `n` | Кількість виміряних запусків задачі. |
| Мінімальний час | `min_us` | Найменша тривалість виконання, мкс. |
| Середній час | `avg_us` | Середня тривалість виконання, мкс. |
| Максимальний час | `max_us` | Найбільша тривалість виконання, мкс. |

Формат повідомлення:

```text
STAT name=<назва> n=<кількість> min_us=<мінімум> avg_us=<середнє> max_us=<максимум>
```

Повідомлення статистики задач виводить `metrics_stats()`.

## 3. Тривалість головного циклу

Для головного циклу `loop` збираються кількість виміряних проходів, мінімальна, середня та максимальна тривалість одного проходу.

Формат повідомлення:

```text
STAT name=loop n=<кількість> min_us=<мінімум> avg_us=<середнє> max_us=<максимум>
```

Результат виводиться функцією `metrics_stats()`.

## 4. Джитер періодичних задач

Джитер визначається як різниця між фактичним інтервалом між двома послідовними запусками задачі та її заданим періодом:

```text
jitter = фактичний інтервал між стартами − заданий період
```

| Метрика | Поле | Опис |
|---|---|---|
| Заданий період | `period_ms` | Період запуску задачі, мс. |
| Мінімальний джитер | `min_us` | Найменше відхилення інтервалу запуску від заданого періоду, мкс. |
| Максимальний джитер | `max_us` | Найбільше відхилення інтервалу запуску від заданого періоду, мкс. |
| Кількість довгих інтервалів | `missed` | Кількість інтервалів між запусками, що перевищили два задані періоди. |

Метрика виводиться для задач `sensors`, `camera`, `flash_log` і `heartbeat` у форматі:

```text
JITTER name=<назва> period_ms=<період> min_us=<мінімум> max_us=<максимум> missed=<кількість>
```

Повідомлення `JITTER` виводить `metrics_stats()`.

## 5. Затримка реакції на кнопку

Для подій натискання кнопки `B1` вимірюється інтервал від фіксації події переривання до обробки прапорця події в основному циклі.

| Метрика | Поле | Опис |
|---|---|---|
| Кількість вимірювань | `n` | Кількість виміряних подій кнопки. |
| Мінімальна затримка | `min_us` | Найменша виміряна затримка, мкс. |
| Середня затримка | `avg_us` | Середня виміряна затримка, мкс. |
| Максимальна затримка | `max_us` | Найбільша виміряна затримка, мкс. |

Результат має назву `btn_latency` і виводиться у форматі:

```text
STAT name=btn_latency n=<кількість> min_us=<мінімум> avg_us=<середнє> max_us=<максимум>
```

Повідомлення виводить `metrics_stats()`.

## 6. Завантаження CPU

Завантаження CPU відображає частку часу вимірювального вікна, витрачену на виконання задач, які враховуються в лічильнику зайнятості.

| Метрика | Поле | Опис |
|---|---|---|
| Завантаження останнього вікна | `pct` | Відсоток завантаження за останнє вимірювальне вікно. |
| Середнє завантаження | `avg` | Середнє значення за всіма вікнами. |
| Максимальне завантаження | `max` | Найбільше зафіксоване значення. |
| Кількість вікон | `n` | Кількість завершених вікон вимірювання. |

Повідомлення має формат:

```text
LOAD pct=<поточне> avg=<середнє> max=<максимум> n=<кількість вікон>
```

Результат виводить `metrics_load_report()`.

## 7. Журнал подій

Журнал містить часові мітки та назви подій. Для записів використовується кільцевий буфер на 128 елементів.

| Назва події | Значення |
|---|---|
| `btn_press` | Натискання кнопки. |
| `btn_react` | Реакція на кнопку. |
| `cmd_rx` | Отримання команди. |
| `cmd_done` | Завершення команди. |
| `capture_start` | Початок захоплення кадру. |
| `capture_done` | Завершення захоплення кадру. |
| `flash_start` | Початок операції з flash. |
| `flash_done` | Завершення операції з flash. |

Звіт містить кількість збережених записів (`n`), кількість витіснених записів (`dropped`), часову мітку в мікросекундах (`t_us`) і назву події (`name`).

```text
--- EVT n=<кількість записів> dropped=<кількість витіснених записів> ---
EVT t_us=<час> name=<назва події>
--- EVT end ---
```

Повідомлення журналу виводить `metrics_evt_dump()`.

## 8. Використання стека

Вимірюються зарезервований розмір стека, використаний обсяг і вільний залишок.

| Метрика | Поле | Опис |
|---|---|---|
| Зарезервований розмір | `reserved` | Розмір стека, заданий у компонувальнику, байти. |
| Використаний стек | `used` | Виміряний обсяг використаного стека, байти. |
| Вільний залишок | `free` | Різниця між зарезервованим та використаним обсягом, байти. |

Формат повідомлення:

```text
STACK reserved=<байти> used=<байти> free=<байти>
```

Результат виводить `metrics_stack_report()`.

## 9. Звіт про heap

Звіт містить зарезервований розмір heap і поле використання пам’яті.

```text
HEAP reserved=<байти> used=<байти>
```

Повідомлення виводить `metrics_heap_report()`.

## 10. Службові GPIO

Службові GPIO використовуються для зовнішнього спостереження за тривалістю виконання задач за допомогою логічного аналізатора.

| Канал | GPIO | Задача |
|---:|---|---|
| 0 | PA4 | `uart_rx` |
| 1 | PB0 | `sensors` |
| 2 | PB1 | `camera` |
| 3 | PB10 | `flash_log` |

Ширина імпульсу на відповідному контакті показує інтервал від початку до завершення вимірюваної задачі.

## 11. Початкове повідомлення

Під час ініціалізації прошивка виводить версію прошивки, частоту ядра та призначення контактів службових GPIO:

```text
METRICS fw=<версія> clk=<частота> Hz probes=PA4,PB0,PB1,PB10
```

Це повідомлення виводить `metrics_init()`.

## 12. Підсумок повідомлень із метриками

| Повідомлення | Що містить | Функція виведення |
|---|---|---|
| `METRICS` | Версія прошивки, частота ядра, контакти GPIO probes | `metrics_init()` |
| `STAT` для задач | Кількість, мінімальний, середній і максимальний час виконання | `metrics_stats()` |
| `STAT name=loop` | Кількість проходів і мінімальна, середня та максимальна тривалість циклу | `metrics_stats()` |
| `STAT name=btn_latency` | Кількість вимірювань і мінімальна, середня та максимальна затримка реакції на кнопку | `metrics_stats()` |
| `JITTER` | Період, мінімальний і максимальний джитер, кількість довгих інтервалів | `metrics_stats()` |
| `LOAD` | Завантаження останнього вікна, середнє та максимальне завантаження, кількість вікон | `metrics_load_report()` |
| `EVT` | Часові мітки та назви подій, кількість записів і витіснених записів | `metrics_evt_dump()` |
| `STACK` | Зарезервований, використаний і вільний обсяг стека | `metrics_stack_report()` |
| `HEAP` | Зарезервований розмір heap і поле використання | `metrics_heap_report()` |
